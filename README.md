# chatlog (챗로그)

## 설치

### 1. 클라이언트 확장 (깃허브 설치)
ST → 확장 → Install extension → 이 저장소 URL 붙여넣기

수동 설치라면 저장소 전체를:
```
SillyTavern/data/<사용자 폴더>/extensions/chatlog/
```

### 2. 서버 플러그인 연결

설치 전에 SillyTavern 서버를 완전히 종료하세요. 스크립트는 기존 `data.json`·`settings.json`을 확장 안의 서버 폴더로 옮기고, 기존 플러그인 폴더와 `config.yaml`을 백업한 뒤 바로가기를 만듭니다.

Termux:

```bash
cd ~/SillyTavern/data/default-user/extensions/chatlog
bash install-termux.sh ~/SillyTavern
```

Windows PowerShell:

```powershell
cd "C:\SillyTavern\data\default-user\extensions\chatlog"
Set-ExecutionPolicy -Scope Process Bypass -Force
Unblock-File .\install-windows.ps1
.\install-windows.ps1 -SillyTavernPath "C:\SillyTavern"
```

설치 중 서버 플러그인 권한 안내에 동의하면 `enableServerPlugins: true`가 자동 적용됩니다. 완료 후 SillyTavern을 다시 실행하세요.

기존 수동 설치에서 전환하는 경우에도 같은 명령을 사용합니다.

- 기존 서버 폴더와 연결 정보는 플러그인 로더가 읽지 않는 `SillyTavern/chatlog-backups/날짜-번호` 아래에 남습니다.
- 기존 `data.json`과 `settings.json`은 새 확장 안의 `server` 폴더로 복사됩니다.
- 기존 `config.yaml`도 같은 `chatlog-backups/날짜-번호` 폴더에 보관됩니다.
- 설치 후 `plugins/chatlog`는 확장 안의 `server` 폴더를 가리키는 바로가기가 됩니다.
- 이후 GitHub 확장 업데이트로 클라이언트와 서버 코드가 함께 갱신되며, 서버 코드 변경을 적용하려면 SillyTavern을 재시작해야 합니다.

### 서버 플러그인 보안 안내

- 자동 게시·예약 댓글·이미지 생성은 서버 플러그인이 담당하므로 `enableServerPlugins: true`가 필요합니다.
- 서버 플러그인은 일반 브라우저 확장보다 권한이 큽니다. 출처를 신뢰하는 플러그인만 `plugins` 폴더에 설치하세요.
- Cloudflare Tunnel 등으로 SillyTavern을 외부에 공개한다면 반드시 SillyTavern 로그인 보호를 켜고 공개 주소를 공유하지 마세요.
- API 키, `server/data.json`, `server/settings.json`은 GitHub나 배포 ZIP에 포함하지 마세요.
- 챗로그는 관리 이미지의 읽기·등록·삭제 경로를 지정된 SillyTavern 폴더 내부로 제한합니다.
- 캐릭터·페르소나 참고 이미지는 선택한 사용자 데이터 폴더 또는 `public`의 지정된 이미지 폴더에서만 읽습니다.
- 텍스트·이미지 생성 연결은 Vertex AI 프로필만 허용하며, Vertex 및 Google OAuth 공식 주소 이외의 임의 호스트로 인증 요청을 보내지 않습니다.

### 3. 설정
확장 탭 → chatlog
- 실리태번에서 현재 선택한 연결 프로필 자동 사용 (기본값, 체크 해제 시 수동 선택)
- 이미지 인증에 사용할 실리태번 Vertex 연결 프로필 선택
- 이미지 키·프로젝트 ID·리전은 선택한 프로필과 실리태번 설정에서 자동으로 읽음
- 이미지 모델은 챗로그에서 나노바나나 모델 중 별도로 선택
- 활동 시간대 / 게시 판단 주기 / 최대 게시 공백 / 댓글 지연
- 캐릭터 카드를 일상 생성의 최우선 근거로 사용
- 최근 채팅의 현재 관계와 공유된 사건을 캐릭터 일상에 반영
- 새 단톡 생성 시 연결된 페르소나들의 프사·이름 중 화면에 표시할 페르소나 선택
- 새 단톡 생성 직후 표시 페르소나와 캐릭터별 관계·호칭·금지 호칭을 직접 설정
- 기본 관계 목록에 없는 관계는 **직접 입력**으로 자유롭게 저장
- 직접 저장한 관계는 방 전용 고정값이며 AI 분석보다 우선
- 필요할 때 관계 편집기의 **AI 제안으로 채우기**로 카드·연결 페르소나·최근 채팅 기반 제안을 받을 수 있음
- 댓글·반응마다 화자 ID와 대상 ID를 검증해 표시 페르소나/개인 연결 페르소나 혼선을 차단
- 화면 표시 페르소나와 AI 관계 페르소나를 분리해, 각 캐릭터는 자신에게 연결된 페르소나의 설명·관계·사진을 참고
- 각 캐릭터의 연결 페르소나 이름·프사 메타데이터와 맞는 최근 채팅을 우선 선택
- 연결 페르소나가 없는 캐릭터는 단톡의 표시 페르소나를 기본값으로 사용
- 기존 단톡 상단의 페르소나 버튼으로 화면 표시 페르소나를 언제든 변경
- 유저의 행동·신체 상태는 유저에게, 캐릭터의 행동·신체 상태는 캐릭터에게 정확히 유지
- 사람이 등장하는 자동 게시 사진은 게시 캐릭터가 직접 찍은 셀카 구도로 생성
- 설정에서 일상 사진과 셀카의 기본 비율을 합계 100%로 직접 조정
- 셀카 중 연결 페르소나가 함께 나올 확률도 별도로 조정
- 연결 페르소나 동반 사진에는 해당 캐릭터에게 연결된 페르소나의 프사와 설명만 사용
- 최근 셀카 4장에 연결 페르소나가 한 번도 나오지 않았고 동반 확률이 0%가 아니라면 다음 가능한 셀카에서 동반을 우선
- 페르소나가 사진에 등장하면 페르소나 프사와 설명을 별도 인물 참조로 사용
- 현재 날짜·계절·시각에 맞춰 옷차림, 자연광, 식생과 주변 환경을 조정
- 계절만으로 비·눈 같은 정확한 날씨를 임의로 만들지 않으며 장소의 실제 기후 조건을 우선
- 사람 없는 풍경·음식·물건 사진은 일반적인 캐릭터 시점 스냅으로 생성
- 인물 사진은 게시 캐릭터 프사를 필수 참조로 사용하고, 페르소나가 함께 나오면 페르소나 프사도 필수 참조로 사용
- 인물 참조가 없으면 이미지 요청을 보내지 않으며, 참조 없는 텍스트 외형 폴백을 사용하지 않음
- 인물 이미지 요청에서는 캐릭터·페르소나 이름을 Person A·Person B로 익명화해 원작·영화·배우의 학습 외형이 프사를 덮어쓰지 않도록 함
- 인물의 얼굴·머리·나이·체격은 첨부 프사를 유일한 시각 정체성 기준으로 사용하며, 캐릭터 이름·원작·배우·공식 각색 외형을 무시하도록 고정
- 별도의 생성 후 얼굴 검사 API 호출은 하지 않으며, 이미지 데이터가 비거나 요청이 실패하면 같은 참조 프사를 유지한 채 최초 요청 포함 최대 3회 시도
- 이미지가 끝까지 생성되지 않으면 사진 없는 게시물을 저장하지 않음
- 일시적인 생성 실패는 10분 → 30분 → 60분 간격으로 최대 3회 자동 재시도
- 서버가 꺼져 있던 동안의 과거 슬롯은 몰아서 생성하지 않고 건너뛴 뒤 현재 시각부터 재개
- 설정 화면에서 마지막 성공·오류, 대기/재시도 작업, 다음 판단 시각을 확인
- 캐릭터 댓글과 이모지 반응은 한 번의 JSON 생성으로 함께 처리해 호출 수 절감
- 멤버별 댓글 관점을 분산하고 기존 댓글을 함께 제공해 시간대 상투어와 유사 댓글을 줄임
- 한 시간대의 캐릭터 게시 판단은 최대 약 55분 안에서 순차 분산
- 캐릭터 선택 검색, 카드와 같은 비율의 하루로그 GIF, 최상단 토스트, 이미지 사전 로드·DOM 재사용 렌더링 적용
- 캐릭터끼리도 설정한 확률로 댓글을 달며, 이모지 후보는 화면과 서버 모두 10종으로 통일

> 이미지 생성의 `responseModalities: ['Image']`는 Gemini의 이미지 전용 응답 요청 형식이므로 유지합니다.

## 강제 실행

### 슬래시 커맨드 (ST 채팅창)
| 커맨드 | 설명 |
|---|---|
| `/chatlog` | 챗로그 열기 |
| `/chatlog-run` | 대기 댓글 + 캐릭터 반응 + 캐릭터 컷 전부 지금 실행 |
| `/chatlog-run what=comments` | 대기 중인 댓글 작업을 즉시 실행 (묶인 이모지 반응도 함께 처리될 수 있음) |
| `/chatlog-run what=reactions` | 대기 중인 반응 작업을 즉시 실행 (미리 정해진 캐릭터 댓글도 함께 처리될 수 있음) |
| `/chatlog-run what=cut` | 캐릭터 컷만 지금 생성 |
| `/chatlog-run room=우리로그` | 특정 로그만 |
| `/chatlog-now` | 다음 슬롯 시각을 지금으로 당김 (1분 내 실행) |
| `/chatlog-local` | 대기 댓글을 브라우저에서 조용히 생성 (채팅 UI에 안 뜸) |
| `/chatlog-jobs` | 대기 중인 작업 목록 (콘솔에 표로 출력) |

### curl (터먹스에서 직접)
```bash
# 전부 지금 실행
curl -X POST http://127.0.0.1:8000/api/plugins/chatlog/force \
  -H 'Content-Type: application/json' -d '{"what":"all"}'

# 댓글만
curl -X POST http://127.0.0.1:8000/api/plugins/chatlog/force \
  -H 'Content-Type: application/json' -d '{"what":"comments"}'

# 다음 슬롯 당기기
curl -X POST http://127.0.0.1:8000/api/plugins/chatlog/force/now \
  -H 'Content-Type: application/json' -d '{}'

# 대기 작업 확인
curl http://127.0.0.1:8000/api/plugins/chatlog/jobs

# 자동 실행 성공/오류/재시도 상태
curl http://127.0.0.1:8000/api/plugins/chatlog/status

# 방과 게시물 데이터
curl http://127.0.0.1:8000/api/plugins/chatlog/state
```
포트는 ST 설정에 맞게 바꾸세요. ST 로그인 보호를 사용한다면 `-u 아이디`를 추가하고,
터미널에 비밀번호 입력 요청이 뜰 때 로그인 비밀번호를 입력하세요. 명령어에 비밀번호를 직접
적으면 셸 기록에 남을 수 있으므로 권장하지 않습니다.

### 데이터 위치
```
plugins/chatlog/data.json       # 방 / 게시물 / 작업 큐
plugins/chatlog/settings.json   # 플러그인 설정
public/user/images/chatlog/     # 생성된 이미지
```
작업 큐에 문제가 생기면 먼저 챗로그 상태와 터미널 로그를 확인하세요.
`data.json`을 직접 편집하면 데이터가 손상될 수 있으므로, 편집이 꼭 필요하다면
SillyTavern을 종료하고 파일을 백업한 뒤 진행하세요.

## 저장 / 정리

- 게시물 하단 **저장** — 사진 파일 다운로드
- 게시물 하단 **보관** — 자동 삭제 대상에서 제외
- 하루로그 → **GIF 저장** — 같은 시간대에 올라온 사진을 한 장면 안에 나란히 배치한 실제 GIF로 내보내기
- 확장 탭 → **지난 기록 자동 삭제** — N일 지난 게시물·사진·하루로그 영상 일괄 삭제 (하루 한 번 자동, 또는 "지금 정리")

## v0.7.1 변경 사항

- 캐릭터별 연결 페르소나와 일치하는 최근 채팅 우선 선택
- 실패 작업 10분/30분/60분 자동 재시도
- 설정 화면 자동 실행 상태 표시
- 기존 단톡 표시 페르소나 변경
- 서버 중단 중 밀린 슬롯 건너뛰기
- 캐릭터 댓글+반응 1회 호출로 통합
- 캐릭터끼리 댓글 달 확률 설정
- 브라우저/서버 이모지 후보 10종 통일

## v0.7.2 수정

- Vertex Express API 키가 표준 Vertex 프로젝트 경로로 전송되어 OAuth2 401이 발생하던 문제 수정
- 텍스트 판단과 이미지 생성 모두 프로젝트 ID·리전이 없는 Express 전용 전역 경로 사용
- 기존 프로젝트 ID·리전 설정값은 호환을 위해 보존하지만 Express 모드에서는 사용하지 않음

## v0.7.3 변경 사항

- 캐릭터끼리 댓글·이모지 반응을 만들 때 댓글 작성자와 게시물 작성자의 캐릭터 카드를 모두 참고
- 댓글 작성자 카드를 말투·성격·행동의 최우선 기준으로 명시
- 게시물 작성자 카드는 상대 정보와 두 캐릭터 사이의 관계·호칭·과거·위계 확인용으로 분리
- 상대 캐릭터의 말투가 댓글 작성자에게 섞이거나 카드에 없는 관계를 임의로 만드는 현상 방지

## v0.7.4 변경 사항

- 설정 화면을 항목명과 입력칸이 나란히 놓이는 가로형 레이아웃으로 정리
- 숫자 입력칸과 테스트·새로고침·정리 버튼을 내용에 맞는 짧은 너비로 조정
- 긴 서버 오류는 화면에 요약만 표시하고 전체 내용은 제목 도움말로 확인
- 챗로그 데이터를 먼저 불러온 뒤 화면을 한 번만 표시해 열 때 발생하던 깜빡임 완화
- 채팅 입력창 옆에 🙃 빠른 열기 버튼과 읽지 않은 게시물·댓글 개수 뱃지 추가

## v0.8.7 변경 사항

- 이미지 모델에 전달되는 캐릭터·페르소나 이름을 `Person A`·`Person B`로 익명화해 유명 원작명이나 배우의 학습 외형이 프사를 덮어쓰는 현상 완화
- 인물의 얼굴·머리·나이·피부·체격을 첨부 프사의 픽셀만으로 결정하도록 참조 이미지 정체성 잠금 강화
- 원작, 영화, 드라마, 공식 각색, 배우, 연예인, 팬아트와 닮은 외형을 대신 생성하지 말라는 명시적 차단 규칙 추가
- 인물 이름과 텍스트 모델의 외형 설명은 이미지의 얼굴 정체성 결정에 사용하지 않고 장면 판단에만 사용
- 기존 두 번의 이미지 시도가 모두 실패할 경우 같은 프사를 유지한 정체성 우선 프롬프트로 한 번 더 재생성해 최초 요청 포함 최대 3회 시도
- 인증·권한·할당량 오류는 기존처럼 추가 요청 없이 즉시 중단해 불필요한 비용 방지

- 프로젝트 ID가 프로필에 명시된 Express 연결과 Full OAuth 연결의 기존 project-scoped 경로는 유지

- Windows·Termux 설치 백업을 `plugins` 바깥의 `chatlog-backups`에 저장하도록 변경
- 이전 서버 연결이 삭제되어 깨진 Junction·심볼릭 링크가 남아 있어도 새 연결로 복구
- 기존 서버의 `data.json`·`settings.json`은 새 서버 폴더로 옮겨 게시물과 설정을 보존
- 서버 백업 항목을 SillyTavern이 플러그인으로 오인해 전체 플러그인 로딩이 중단되던 문제 수정

- SillyTavern 로그인·CSRF 보호에 더해 다른 출처의 브라우저 요청을 거부하고 변경 요청은 JSON만 허용
- 관리 API 오류 응답에서 프로젝트 ID·프로바이더 본문 같은 상세 인증 정보를 제거하고 원문은 로컬 터미널에만 기록
- 브라우저에서 관계·캐릭터·게시물 값을 HTML 속성에 넣을 때 따옴표까지 이스케이프하고 동적 토스트도 HTML로 해석하지 않도록 변경

- AI 생성 이미지도 최대 크기와 실제 PNG·JPEG·WebP 시그니처를 확인한 뒤 전용 폴더에 저장
- 수동 업로드 이미지는 최대 크기와 실제 시그니처를 검사하고 지원 형식의 위치·촬영 메타데이터를 제거한 뒤 저장
- JPEG는 실제 EOI 뒤의 데이터를 버리고 개인정보 메타데이터 제거 후 구조를 다시 확인
- 하루로그 자동 정리가 심볼릭 링크·Junction을 따라 챗로그 폴더 밖 파일을 삭제하지 못하도록 실제 경로 검증 강화
- `data.json`과 `settings.json`을 임시 파일에 완전히 쓴 뒤 교체하는 원자적 저장으로 변경
- 플러그인 종료 시 예약 타이머를 해제하고 대기 중인 데이터 저장을 마무리해 리로드 중 중복 실행과 유실 가능성 완화
- 설치 스크립트는 Junction·심볼릭 링크나 `config.yaml`을 바꾸기 전에 서버 JavaScript 문법을 먼저 검사
- 기존 방·관계·게시물·설정 데이터 형식과 설치 경로는 유지

## v0.9.2 변경 사항

- 다른 출처의 브라우저 요청을 거부하고 변경 요청은 JSON 형식만 허용
- 이미지 테스트와 강제 실행은 동시 중복을 막고 완료 후 30초 재호출 제한 적용
- 리로드·수동 정리에도 짧은 중복 실행 방지 적용
- 상세 AI 응답 디버그는 기본적으로 기록하지 않으며 설정에서 명시적으로 켠 동안만 최근 10건 보관
- 디버그를 다시 끄면 메모리에 있던 상세 응답도 즉시 삭제
- 삭제 요청의 방·게시물 ID, 소속 관계, 이미지 경로를 재검사하고 연결된 대기 작업도 함께 제거
- 설정 API의 숫자 범위·불리언·이미지 모델 형식을 검증하고 구버전 직접 입력 인증값 변경 차단
- 방 생성·수정 입력을 검증하고 허용되지 않은 필드로 방 ID·내부 상태를 덮어쓰는 요청 차단
- 수동 업로드 JPG·PNG·WebP·GIF에서 EXIF·XMP·IPTC·위치·촬영정보성 텍스트 메타데이터 제거
- 메타데이터를 안전하게 제거할 수 없는 AVIF는 저장하지 않고 JPG·PNG·WebP 변환 안내
- 휴대폰 JPEG는 브라우저에서 촬영 방향을 먼저 화소에 반영한 뒤 서버에서 메타데이터를 다시 제거
- 비정상적으로 큰 JPEG는 브라우저 메모리 보호를 위해 업로드 전 거부

챗로그는 현재 **한 SillyTavern 인스턴스를 한 사용자가 쓰는 환경**을 기준으로 합니다.
여러 계정이 같은 SillyTavern 서버를 함께 쓰는 환경의 방별·사용자별 데이터 격리는 제공하지 않습니다.

## v0.9.0 변경 사항

- **같은 방 캐릭터 공동 장면**: 관계와 성격을 바탕으로 2~3명이 카페·식사·산책·쇼핑·운동·실내 모임에 함께 있는 시간대를 만들 수 있습니다.
- **같은 시간대 다중 시점**: 첫 게시물이 장소·조명·공유 사물을 확정하면, 다른 참석자는 같은 시간 탭에서 다른 구도와 피사체로 이어서 올립니다.
- **참석자와 사진 등장 인물 분리 저장**: 현장에 있었지만 프레임 밖인 인물과 사진에 실제로 나온 인물을 별도로 기록합니다.
- **댓글 참석 여부 잠금**: 사진에 없는 캐릭터가 “나 잘 나왔네”라고 하거나, 현장에 없던 캐릭터가 같이 있었다고 말하는 댓글을 생성 단계와 저장 단계에서 차단합니다.
- **공동 셀카 얼굴 기준 강화**: 함께 나온 방 캐릭터 각각의 프사를 별도 참조 이미지로 전달하고 얼굴이 합쳐지거나 서로 바뀌지 않도록 잠급니다.
- **비용 조절 설정**: `같은 방 공동 장면`과 `추가 참석자 게시` 확률을 각각 0~100%로 조절할 수 있습니다. 공동 장면 계획 자체는 별도 AI 요청을 추가하지 않으며, 실제 추가 게시가 생길 때만 기존 게시물과 같은 텍스트·이미지 요청 비용이 듭니다.

## v0.8.9 변경 사항

- SillyTavern 1.18에서 카메라 촬영·갤러리 선택 사진이 `invalid image path`로 거부되던 문제 수정
- 수동 사진을 챗로그 서버의 전용 업로드 경로로 받아 `public/user/images/chatlog`에 직접 저장

- 게시·저장·삭제가 모두 같은 챗로그 전용 경로 보호 규칙을 사용하도록 통일
- 자동 정리 중 사진이 없는 게시물의 `null` 값을 외부 경로로 오인해 삭제 거부 로그를 반복하던 문제 수정
- 같은 게시물뿐 아니라 방 전체의 최근 캐릭터 댓글까지 비교해 문장 구조·핵심 소재·명령형 결론이 반복되는 댓글 차단
- 첫 댓글이 최근 표현과 겹치면 다른 사진 세부사항과 관점으로 한 번만 재작성하고, 다시 겹치면 댓글은 생략하고 이모지 반응만 유지
